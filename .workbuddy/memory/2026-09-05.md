## Settings 页面升级 — 对齐后端新版 OpenAI API / 多供应商

后端 `Turbo.Auth` 已经把 `NoModelChatBody` 扩展出 `reasoning_effort` / `verbosity` / `thinking_budget`，并由 `OpenAiChatHandler`（o 系列、gpt-5 系列）和 `GoogleChatHandler`（Gemini 2.5）按模型兼容性过滤。`ProviderCatalog` 把 OpenAI / Google / Anthropic / Alibaba / Novita / Twitter / ApiMart 都登记好了。Settings 页面之前只透传老 OpenAI 套词，这次把前端也对齐。

### 改动文件

- `src/models/enumerates/enum.type.ts` — 新增 `HandlerType` enum、`ProviderDefinition` 接口、`providerCatalog` 常量、`reasoningEfforts` / `verbosityLevels` / `thinkingBudgetPresets` 列表，严格对齐后端 `ProviderCatalog`。
- `src/models/enumerates/index.ts` — `export type {ProviderDefinition}`（因为 tsconfig 启用了 `isolatedModules`，类型再导出必须用 `export type`）。

- `src/services/fetch_services/turbo.service.ts` — `fetchChat` 通过 `appendIfPresent` / `appendIfNumber` 仅在用户显式配置时把字段加进请求体；缺失时不发送，与旧版本行为完全兼容。
- `src/pages/settings/settings.html` — 在「对话默认属性」card 之后新增「扩展对话参数」card（reasoning_effort / verbosity / thinking_budget 三栏下拉），以及「支持的服务商」展示卡（只读）。

- `src/assets/i18n/{zh,en,jp}.json` — 新增 14 个 i18n key（`advancedChatParameters*`、`reasoningEffort*`、`verbosity*`、`thinkingBudget*`、`providerCatalog*`、`optionNotSet` 等）。

### 验证

`ng build --configuration development` 通过（4.1s）；`tsc -p tsconfig.app.json --noEmit` 零错误。

### 注意点

- `ChatStreamConfiguration` 新字段都是 optional，旧版本地数据库里的配置对象不需要迁移即可工作。
- `thinkingBudget` 用 `null` 表示「不发送」（与 `undefined` 等价），整数 `-1` = 动态思考，`0` = 不思考。
- 后端 `OpenAiChatHandler` 内部对 reasoning 模型会忽略 `temperature / top_p / penalties`，SDK 不支持时会走原生 HTTP 通道。前端不需要做特殊判断。
- 服务商目录是只读参考，密钥维护仍走 admin 控制台的 secrets 模块。

## 紧凑端 (<=900px) 工作室抽屉式遮罩

AI绘画 / 多媒体 / AI对话 三个工作室的左侧导航菜单，在小屏幕下原本因为 `.menu { max-width: none }` + `w-100` 而把右侧内容挤压。统一改为抽屉 + 遮罩浮层：紧凑模式下侧边栏以 `position: absolute` 浮在内容之上，背后铺一层半透明 `.menu-backdrop`，点击遮罩关闭，点击抽屉内任一选项也关闭（桌面端行为完全不变）。

### 改动文件

- `src/styles.css` — 全局新增 `.menu-backdrop`（absolute / 半透明黑 / z-1040），在 `@media (max-width: 900px)` 内追加 `.menu.menu-overlay`（absolute / 250px max 80vw / z-1050 / 阴影）。
- `src/pages/imageStudio/top-image/top-image.html` & `.ts` — 外层 `position: relative`；`@if(isCompact())` 渲染 `.menu-backdrop`；菜单 div `[class.w-100]="!isCompact()"` + `[class.menu-overlay]="isCompact()"`；三个子页按钮 + 底部三栏工作室按钮全部 `(click)="closeMenuIfCompact()"`。ts 新增 `isCompact() / hideMenu() / closeMenuIfCompact()`。
- `src/pages/multi-media-center/top-media/top-media.html` & `.ts` — 同上，对应三个 `mediaStudio.*` 按钮。
- `src/pages/chat-page/chat-page.html` & `.ts` & `.scss` — `chat-page.scss` 原本就有 `@media (max-width: 900px) { .app-sidebar { position: absolute; ... z-index: 20 } }`，无需再加 overlay CSS，只需补齐遮罩和点击关闭。`.screen-content` 加 `position: relative`；scss 在 `@media (max-width: 900px)` 内增加 `.menu-backdrop { z-index: 19 }`（让遮罩坐在侧边栏 20 之下）。html 在 `@if(visible())` 内增加 `@if(isCompact()) { <div class="menu-backdrop" (click)="hideMenu()"> }`；三个工作室按钮 `(click)="closeMenuIfCompact()"`；`openSettingPage / openPromptPage` 在 TS 内第一行调用 `closeMenuIfCompact()`。ts 新增 `isCompact() / hideMenu() / closeMenuIfCompact()`。

### 验证

`ng build --configuration development` 通过：第一次 5.127s，第二次（含 chat-page）4.675s，均零模板/类型错误。`dist/app/browser/assets` 目录的清理被 sandbox safe-delete 拦截（无关代码），属预期。

### 注意点

- `SizeReportService.menuVisible` + `miniPhoneView()`（`<= 900` 阈值）是整套抽屉行为的判定依据，所以不需要在每页再监听 resize。
- 浮层抽屉的关键是父容器 `position: relative`，否则 `position: absolute` 会回退到初始包含块（视口），遇到带 transform 的祖先时会失效。
- `menu-backdrop` 在三个工作室里分别需要不同的 z-index：top-image/top-media 用 1040（已在 styles.css 全局定义），chat-page 用 19（侧边栏是 20）。所以 chat-page 在组件 scss 内做了覆盖。
- 在桌面端 (>900px)，所有改动对原行为零影响。
