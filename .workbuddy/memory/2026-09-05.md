## 紧凑端 (<=900px) 工作室抽屉式遮罩

AI绘画 / 多媒体 / AI对话 三个工作室的左侧导航菜单，在小屏幕下原本因为 `.menu { max-width: none }` + `w-100` 而把右侧内容挤压。统一改为抽屉 + 遮罩浮层：紧凑模式下侧边栏以 `position: absolute` 浮在内容之上，背后铺一层半透明 `.menu-backdrop`，点击遮罩关闭，点击抽屉内任一选项也关闭（桌面端行为完全不变）。

`ng build --configuration development` 通过：第一次 5.127s，第二次（含 chat-page）4.675s，均零模板/类型错误。`dist/app/browser/assets` 目录的清理被 sandbox safe-delete 拦截（无关代码），属预期。

- `SizeReportService.menuVisible` + `miniPhoneView()`（`<= 900` 阈值）是整套抽屉行为的判定依据，所以不需要在每页再监听 resize。

## 图像工作室仓库 (task-lib) 新增批量删除

`imageStudio/task-lib` 是图像工作室的仓库（生成任务历史）页面。原来只能逐条删除，新增批量删除：工具栏加一个红色 nzDanger 按钮「批量删除」，点击后弹出 nz-modal，里面以 `nz-list` 列出当前 `generateTasks`，每条带一个 `nz-checkbox`，顶部有「全选/取消全选」按钮 + 「已选 N/M」文字。

### 删除策略（部分出错不影响整体）

`confirmBatchDelete` 顺序遍历 `selectedTaskIds`：

1. 优先通过 `SendManagerService.deleteTask(taskId)` 调后端删除；
2. 成功后再调 `UniversalService.deleteGenerateTask(task)` 删本地 IndexedDB；
3. 任意一步抛错就 catch，把 `{taskId, reason}` 推入 `failedItems`，继续下一条；
4. 任务对象在 `tasksById` 里找不到则记入 `skippedItems`；
6. 成功 ID 在循环结束后从 `generateTasks` 中过滤移除。

最后调 `showBatchDeleteResult`：

- 全部成功 → `notification.success`，文案只显示「成功 N 个」；
- 有失败 / 跳过 → `notification.warning`（`nzDuration: 8000`），文案含失败明细和跳过明细（多行）。

### 改动文件

- `src/pages/imageStudio/task-lib/task-lib.html`
  - 工具栏右侧新加 `<button nzDanger>` 批量删除按钮（`generateTasks.length === 0` 时禁用）；
  - 文件末尾新加 `<nz-modal batchDeleteVisible>`，含顶部「已选 N/M + 全选按钮」、`<nz-list [nzLoading]="batchDeleteRunning">`、`<label nz-checkbox [(ngModel)]="selectedTaskIds.has(...)">`，以及 `@empty` 块渲染 `<nz-empty>`。
- `src/pages/imageStudio/task-lib/task-lib.ts`
  - 新增 imports：`SendManagerService`、`NzModalModule`、`NzCheckboxComponent`、`NzListModule`、`NzEmptyComponent`、`NzColDirective`；
  - 新增字段 `batchDeleteVisible / batchDeleteRunning / selectedTaskIds: Set<string>`；
  - 新增方法 `openBatchDelete / closeBatchDelete / toggleTaskSelection / isAllSelected / toggleSelectAll / confirmBatchDelete / formatError / showBatchDeleteResult`；
  - 注意：`deleteTask` 方法在 `SendManagerService` 上，不在 `RequestManagerService` 上（之前误用过了）。
- `src/assets/i18n/zh.json / en.json / jp.json`
  - `image` 节点内新增键：`batchDelete / batchDeleteTitle / batchDeleteHint / batchDeleteEmpty / batchDeleteConfirm / batchDeleteSuccessTitle / batchDeletePartialTitle / batchDeleteResult`。最后一条用占位符 `{{success}} / {{fail}} / {{skip}} / {{failedIds}} / {{skippedIds}}` 携带明细。

### 验证

### 注意点

- 用 `Set<string>` 存选中状态；切换全选时直接重新构造一个新的 Set，不要 `clear()` + add 回填，否则 Angular 变更检测可能不会触发模板刷新。

## 批量删除国际化遗漏：`image.selectAll` / `image.deselectAll`

发现 `task-lib.html` 第 55 行的全选/取消全选按钮：

虽然模板里的 translate pipe 调用正确，但 `src/assets/i18n/{zh,en,jp}.json` 中**没有** `image.selectAll` / `image.deselectAll` 两个键，截图里直接显示成了原始字符串 `image.deselectAll`。补齐三个语言文件即可。

## Settings — 单次回复限制新增「无限制」开关 + 拖动条宽度统一

按用户反馈两件事：

1. **新增「无限制」（maxTokensUnlimited）开关**：之前 `maxTokensPerInteraction` 的拖动条最小值是 `0`，并且 `turbo.service.ts` 把 `0` 当作「不发送 max_completion_tokens」处理，但 `0` 仍混在合法数值范围里，对模型实际处理不直观。某些模型对 `max_completion_tokens` 有更严格的上限（例如某些模型只支持 5000 以下），如果用户配置了 10000，会导致请求失败。改为显式的开关：
   - 开启「无限制」时，slider 和 input-number 都被禁用，配置值置为 `undefined`，请求体根本不会带 `max_completion_tokens`，由后端使用模型自身的默认值。
   - 关闭时恢复之前的值（如果在打开开关前有过有效数值）或回落默认值 4000。
   - 同时兼容历史配置中以 `0` 表示「不限制」的情况。
2. **拖动条宽度统一**：原来这一行的 `nz-slider` 用了 `class="slider big"`（宽度 200px），与同行其他 sliders（`slider` = 100px）不一致。改成 `class="slider"`，与同 card 内其他 sliders（temperature、top_p、presence_penalty、frequency_penalty、historySessionLength）保持同一宽度。

### 改动文件

- `src/pages/settings/settings.html` — `slider big` → `slider`；新增第三个 `nz-col` 放「无限制」开关 + tooltip 提示文案；slider / input-number 都加上 `[nzDisabled]="isMaxTokensUnlimited()"`；slider / input 改为 `[ngModel]="maxTokensSliderValue()"` + `(ngModelChange)="updateMaxTokensSlider($event)"` 单向绑定（因为 disabled 时滑块值就是 DEFAULT_MAX_TOKENS = 4000，需要函数来桥接 undefined 状态）。
- `src/pages/settings/settings.ts` — 新增 `private static DEFAULT_MAX_TOKENS = 4000`、`previousMaxTokensValue` 历史值，以及四个方法：`isMaxTokensUnlimited()` / `setMaxTokensUnlimited(boolean)` / `maxTokensSliderValue()` / `updateMaxTokensSlider(value)`。`maxTokensSliderValue` 在 unlimited 时返回 4000 作为显示值，避免 slider 自身 undefined 报错；`updateMaxTokensSlider` 兜底把用户拖到 0 的边界情况拦截并回落到上次保留值。
- `src/services/fetch_services/turbo.service.ts` — 把原来的 `if(tokens===0){ tokens=null; }` 抽成独立的 `resolveMaxCompletionTokens(value)`：undefined / null / 0 / 负数 / 非有限数 全部归一化为 `undefined`，由 `appendIfNumber` 跳过该字段从而不进入请求体。这样无论用户在 settings 里把它设成 `0` 还是 `undefined`，传到后端的请求都不会带 `max_completion_tokens`，彻底杜绝错误值。
- `src/assets/i18n/{zh,en,jp}.json` — 在 `settings.maxTokenUsagePerInteraction` 之后新增两个 key：`maxTokensUnlimited`（简短标签「无限制 / Unlimited / 無制限」）和 `maxTokensUnlimitedHint`（详细说明 tooltip 文案）。

### 验证

`ng build --configuration=development` 通过，零模板/类型错误。

### 注意点

- `nz-tooltip` 在 `nz-col` 上直接挂指令是允许的（项目里 `back-to-top` 按钮也是同样写法），tooltip 会以气泡方式出现在「无限制」文字上。
- 如果用户从来没动过这一项（保留默认 4000），开启无限制再关闭，会回到 4000。这是有意为之——`previousMaxTokensValue` 只在「开无限之前确实有正值」时记录。
- `maxTokensSliderValue` 返回的 4000 在 unlimited 状态下只是给 slider 的显示占位，并不写回 config（因为 `[nzDisabled]="isMaxTokensUnlimited()"` 会让滑块事件被禁用，写不进去也没差）。
- `previousMaxTokensValue` 是组件实例字段，没法跨页持久化。极端情况：用户先开无限制 → 关闭页面 → 再打开页面，会从 DEFAULT_MAX_TOKENS 4000 起步。这是可接受的，因为保存到 IndexedDB 的就是 4000。
